# 提交前检查清单

范围与规则

- [ ] 读了 `CONSTITUTION.md`、`AGENTS.md`、`TASK.md`、当前模块 README？
- [ ] 本轮复述块已写入 `TASK.md` 的「轮次记录」？
- [ ] 只改了 `SCOPE:MODIFY` / `SCOPE:CREATE` 白名单内的文件？`scope-check` 通过？
- [ ] `TASK.md` 的白名单没有被自己悄悄扩大？
- [ ] 这次改动属于当前任务卡，不是"顺手"做的别的事？
- [ ] 计划如果有变，`TASK.md` 的计划与 `ROADMAP.md` 已同步？

不可协商项

- [ ] 没有为了让测试通过而修改、删除或跳过测试？测试变更已在「测试变更申报」写明理由？
- [ ] 没有无理由的 `eslint-disable` / `@ts-ignore` / `# noqa`？没改 lockfile / CI / 迁移 / 凭据文件？
- [ ] 没有新增依赖（若新增，是否已走「范围变更请求」并获批）？
- [ ] 没有 `reset --hard` / `push --force` / `--no-verify`？

代码质量

- [ ] 控制流线性、早返回，嵌套不超过 3 层？
- [ ] 没有无意义抽象、没有为小函数单独建文件、没有单行转发的包装层？
- [ ] 类型、错误、副作用、边界都显式？命名没有空词、与术语表一致？
- [ ] `TODO` 都带了任务 ID？
- [ ] 新增写法与既有模块风格一致（错误处理、日志、配置、数据访问）？

验证与记录

- [ ] 涉及行为变化的，红 → 绿证据都记录了？
- [ ] 相关测试已跑过，`scripts/verify.* --full` 全绿，`consistency-audit` 0 error？
- [ ] `TASK.md` 已更新（状态 / 变更文件 / 验证 / 风险 / 下一步）？
- [ ] 架构或依赖方向有变化吗？有则已更新 `ARCHITECTURE.md` 并新增 ADR？
- [ ] 公开接口有变化吗？有则模块 README 与 `docs/contracts/` 已同步（使用方也在同一任务内改完）？

收尾

- [ ] 两阶段评审（`.agents/checklists/task-review.md`）都过了？
- [ ] 已输出最终报告（目标 / 非目标 / 变更文件 / 行为变化 / 验证 / 一致性 / 风险 / 下一步）？
- [ ] 任务完成的话：已归档到 `{{TASKS_REL}}/`，并把 `ROADMAP.md` 状态更新、指向下一个任务？
