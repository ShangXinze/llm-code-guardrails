任务收尾。规则以 `AGENTS.md` + `CONSTITUTION.md` 为准，本文件只给动作顺序。
（下文提到的目录名已按本仓库的配置替换；若还有对不上的，以 `AGENTS.md` §2 与 `scripts/verify.*`
顶部的路径变量为准 —— 那两个地方是唯一来源。）

1. 按 `.agents/checklists/task-review.md` 做两阶段评审：先规格符合性，再代码质量。有阻断项就回到实现，不标 done。
2. 运行全量验证 `scripts/verify.ps1`（或 `scripts/verify.sh`）：
   确认 scope-check 通过、consistency-audit 0 error。日志路径写进 `TASK.md`。
3. 更新 `TASK.md`：状态、变更文件、测试变更申报、红绿证据（重构类给等价性证据）、数字口径、
   验证结果、一致性审计结果、风险与未决、流程偏差申报、下一步。
4. 接口或数据模型有变化 → 同步模块 `README.md` 与 `docs/contracts/`（使用方必须在同一任务内改完）。
5. 架构或依赖方向有变化 → 更新 `ARCHITECTURE.md` 并新增 ADR（触发判据见 `docs/decisions/README.md`）。
6. 任务完成 → 归档到 `{{TASKS_REL}}/<任务 ID>-<标题>.md`，更新 `ROADMAP.md` 的任务与模块状态，指向下一个任务。
7. 按 `AGENTS.md` §10 输出最终报告：

```
目标 / 非目标
变更文件（含新增、删除）
行为变化（改前 vs 改后）
验证：命令 + 日志路径 + 结果（含红→绿证据；重构类给等价性证据）
范围与测试变更申报情况
一致性审计结果
风险与未决问题
下一步（ROADMAP 里的下一个任务）
```

8. 发现规则本身有问题 → 只在 `TASK.md` 写「规则变更请求 / 宪法修正案」，不要直接改 `AGENTS.md` / `CONSTITUTION.md`。
9. **收尾必问一句：本次有没有撞到"规则 / 模板 / 门禁脚本自身"的毛病？**
   （假红或假绿、路径对不上、提示误导人、规则互相打架、文档自相矛盾……）
   有就写进本技能的 `CHANGELOG.md`（症状 → 改法 → 来自哪个仓库），并把改动同步到项目里的那份副本 ——
   否则这些坑只留在本仓库，下个项目重新踩一遍。
10. 顺手申报流程偏差：本卡有没有"先动代码后补卡面""越界后补手续""临时探针插入又删除"这类事？
    写进 `TASK.md`「流程偏差申报」。卡面的价值在于它是过程记录，不是理想流程的复述。
