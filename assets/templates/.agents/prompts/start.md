按 `AGENTS.md` 执行本轮任务。规则以 `AGENTS.md` + `CONSTITUTION.md` 为准，本文件只给动作顺序，不重复规则。

1. 冷启动读取：`AGENTS.md` → `CONSTITUTION.md` → `ROADMAP.md`（只看当前模块与任务队列队首）
   → `TASK.md` → 当前模块 `README.md` → 相关源码与测试 → `scripts/verify.*` 顶部命令配置。
2. 把复述块写入 `TASK.md`「轮次记录」：目标 / 非目标 / 验收标准 / 允许修改 / 禁止修改 / 风险 / 计划修改文件及理由。
   同时说明本轮生效的宪法条款。
3. 若 `TASK.md` 的 `approval` 是 `human`，**停下来等确认**；是 `auto` 才继续。
4. 任务尚不明确、写不出可判定的验收标准时，改用 recon 模式：只读源码，只写 `docs/notes/`，
   产出「现状说明 + 建议方案 + 建议范围」，确认后转 `mode: execute`。
5. 把计划拆到每步都有精确文件路径、验证命令、预期结果；看不懂项目的人也能照着做。
6. 涉及行为变化时先写会失败的测试、看到它失败，再写实现让它通过；红绿证据写进 `TASK.md`。
7. 逐个文件最小变更：每完成一步就跑相关验证（或 `scripts/verify.* --fast`）并更新 `TASK.md`。
8. 需要动白名单外的文件 → 写「范围变更请求」后停止，不要自行扩权。

不要顺手重构、不要新增依赖、不要修改测试让它变绿、不要跳到别的任务。
