# docs/contracts — 跨模块契约

契约是**模块之间、模块与外部世界之间的约定**。它存在的唯一理由：让并行开发的两边不用猜对方，
让全部模块做完之后拼起来还能跑。

契约先行（`CONSTITUTION.md` 第六条）：先写契约，再写实现；契约变更必须在同一个任务内同步所有使用方。

## 契约范围

应该写进这里：

- 模块对外接口签名与语义（不只是类型，还有"什么情况抛什么错"）
- 数据模型与字段含义、可空性、单位、取值范围
- 错误码 / 错误结构 / 重试语义
- 事件与消息格式
- 外部 API 的请求响应约定
- 命名与术语（`glossary.md`）

不该写进这里：

- 单个模块的内部实现细节 → 放模块 `README.md`
- 与代码一一对应的类型定义（那是代码本身）→ 契约只写"约定与理由"，不抄实现

## 一个契约文件的结构

```
# 契约：<名称>

- 状态：draft | active | deprecated
- 拥有者：
- 使用方：<模块 ID 列表>
- 最后变更：<日期> <任务 ID>

## 约定

（接口签名 / 数据结构 / 错误语义，用代码块写）

## 为什么这样定

（约束、历史包袱、被否掉的替代方案）

## 变更流程

（怎么改、谁批准、使用方怎么同步）
```

## 契约变更的三条硬规则

1. **同一任务内同步**：改了提供方，就必须在同一张任务卡里改完所有使用方。不允许"先改一边"。
2. **破坏性变更升版本或加兼容层**：不能悄悄改语义。
3. **使用方清单必须准确**：`使用方` 字段是检查"有没有漏改"的唯一依据，漏填等于埋雷。
