# {{TASKS_REL}} — 归档任务卡

任务完成后，把填充好的 `TASK.md` 原样归档到这里，命名为 `<任务 ID>-<短横线标题>.md`，
例如 `M2-3-order-cancel.md`。**保留原内容不改**（计划、进度日志、红绿证据、评审结论都留着），
只在文件末尾追加一段「结果摘要」。

## 为什么要归档

1. **交接**：新人或新会话靠它恢复"当时为什么这么改、试过什么、放弃了什么"。
2. **对账**：`consistency-audit` 会检查每个 `done` 的模块在 `{{TASKS_REL}}/` 下有没有归档卡，
   防止"标了 done 其实没人做过"。
3. **防漂移**：下一个任务开工前扫一眼同模块的历史卡，避免重复踩坑或做出与既有决策冲突的实现。

## 命名与索引

- 文件名以任务 ID 开头（`M2-3-...`），保证 `ls` 出来的顺序就是执行顺序。
- 不要手工维护总索引表：`grep -l "任务 ID" {{TASKS_REL}}/*.md` 即可。
  （维护两份列表必然漂移。）

## 归档时必做的三件事

1. 更新 `ROADMAP.md`：任务状态 → `done`；该模块名下任务全 `done` 时，模块状态 → `done`。
2. 更新相关模块 `README.md`：「最后核验日期」改为归档当天，接口有变则同步。
3. 若产生了架构级决策，补一条 ADR 到 `docs/decisions/`。
