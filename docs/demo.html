SKILL · 可执行规范

码矩

给 LLM 写代码立下能被执行的规矩：范围锁死、任务不漂、证据落地、模块写完仍像同一个项目。规则能写成脚本的，就不要只写成文档。

技能 ID llm-code-guardrails · 中文名 码矩

五个目标，各有机制

不是口号清单。每一条都绑着 lint、门禁脚本或审计检查，违规会失败退出。

极强可读性 lint

嵌套、函数长度、复杂度、空词命名 —— 能机检的进 lint，不能机检的写成对照示例。

不偏移 scope-check

唯一计划源 + SCOPE 白名单哨兵块。改范围外文件？门禁直接失败。

逐项完成 TASK 卡

一次一张卡。完成 → 评审 → 归档 → 再取下一个。禁止跳任务、并行开卡。

充分验证 verify

红绿证据、分层验证（fast / full）、日志落盘。声明不算数，命令与输出才算。

整体一致 consistency-audit

宪法、契约、术语表 + 适应度函数。模块多了，合起来还得像同一个项目。

效果对比

没有护栏时

  • 改测试骗绿 —— 验证闭环价值归零
  • 顺手重构 —— diff 无法 review
  • 任务漂移 —— 越做越野，模块不像一个项目
  • 新会话失忆 —— 重复问项目结构
  • 完成无痕迹 —— 声称 done，查无证据

装上码矩之后

  • 白名单外改动 → scope-check exit 1
  • 改测试必须申报 → 未申报视为越界
  • 路径写进配置 → .guardrails.json 单点
  • doctor 只读体检 → 卡在哪一眼看清
  • 审计查漂移 → 文档/依赖/命名/证据

动手试试：范围锁

点选「本次改动」的文件，再点「跑 scope-check」。白名单与 DENY 来自任务卡哨兵块。

TASK.md · SCOPE

蓝实线 = MODIFY/CREATE 白名单 · 虚线 = DENY 禁止

选择要改动的文件，然后运行门禁。

init 档位

冷启动不必一次立宪。按成熟度选档，路径写入 .guardrails.json。

档位铺什么何时用
--level=full 默认 规则文档 + 门禁 + 审计 + doctor + verify 多模块正式开发
--level=scope-only 门禁 + TASK + prompts + ROADMAP 骨架 探索期或已有计划源
--level=lint-only 仅配置与 .gitignore 先配 lint，暂不锁范围
--level=minimal 门禁 + TASK + prompts（旧 --minimal） 已有上位治理体系

设计原则

脚本优先能机检的不要只写 Markdown
单点真相计划 / 白名单 / 路径各只有一处
fail-closed空白名单 = 任何改动都越界
静默失效最危险跳过的检查也要打印原因
警告要收敛33 条噪音 = 0 条警告
人类签字宪法与模块拆分不交给 Agent 代定
